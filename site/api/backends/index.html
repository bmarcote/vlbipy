Backends¶

Abstract base classes defining the backend-agnostic interface. Every backend (CASA, AIPS) must implement these ABCs. The pipeline code operates exclusively through these interfaces so backends are swappable.

Backend Registry¶

backends ¶

Backend registry for vlbipy.

Backends are selected by name via :func:get_backend; the API layer never imports a concrete backend directly. Only the dummy backend is implemented in the API-first milestone; casa and aips are stubs that raise on use.

Backend ¶

Package-agnostic backend: a bundle of six operation components.

Subclasses set :attr:kind and point the *_ops class attributes at their own component subclasses. Components are instantiated in __init__, so a subclass that needs to open a library handle first should do that before calling super().__init__().

Parameters¶

work_dir : str or pathlib.Path Directory holding this backend's data products.

components() ¶

Return the components keyed by their attribute name.

capabilities() ¶

Return {component: [implemented operations]} for this backend.

Lets callers (and users, interactively) see exactly what a backend supports without triggering NotImplementedError.

supports(component, operation) ¶

Return True if component.operation is implemented by this backend.

DummyBackend ¶

Bases: Backend

A logging, in-memory backend that fabricates deterministic results.

Writes no files and requires no external software. Every operation logs what a real backend would do and returns synthetic objects.

Parameters¶

work_dir : str Directory used only to build synthetic paths (never created).

components() ¶

Return the components keyed by their attribute name.

capabilities() ¶

Return {component: [implemented operations]} for this backend.

Lets callers (and users, interactively) see exactly what a backend supports without triggering NotImplementedError.

supports(component, operation) ¶

Return True if component.operation is implemented by this backend.

get_backend(kind, **kwargs) ¶

Return a backend instance for the given kind.

Parameters¶

kind : str Backend identifier: "dummy" (always available), "casa", "aips", or "dask-ms" (require their respective packages to be installed). **kwargs Passed to the backend constructor (e.g. work_dir).

Returns¶

Backend

Raises¶

BackendError If the kind is unknown, not implemented, or its package is missing.

Abstract Interfaces¶

DataOps ¶

Bases: BackendComponent

Ingest raw data and read everything the rest of the pipeline needs to know.

This component is the only one allowed to create the backend's native data product, and the single source of observation metadata.

backend property ¶

The owning backend.

kind property ¶

The owning backend's short identifier (e.g. "casa").

work_dir property ¶

The owning backend's working directory.

is_imported(project_code) ¶

Return True if the project's data is already in the backend's native format.

import_data(project_code, source_names, *, scan_gap=15, files=None, delete=False, **kwargs) ¶

Import raw correlator output (FITS-IDI) into the backend's native format.

Parameters¶

project_code : str Project code; names the output product. source_names : list of str Sources declared in the configuration. scan_gap : int Time gap in seconds that starts a new scan. files : list of str, optional The raw files, in order. delete : bool Overwrite an existing product instead of skipping.

import_uvfits(project_code, uvfits, *, delete=False) ¶

Import a UVFITS file into the backend's native format.

adopt_ms(project_code, ms) ¶

Register an already-existing measurement set as this project's data.

reset_calibration(project_code, *, unflag=True, backup_flags=True) ¶

Return an already-imported dataset to its as-correlated state.

Re-running the pipeline over a dataset a previous attempt already touched otherwise inherits that attempt's flags and corrected data: flags only ever accumulate, so each run starts from a smaller array than the last and the result silently depends on run history.

Parameters¶

project_code : str Project code. unflag : bool Clear every flag (the pipeline re-applies the a-priori flags itself). backup_flags : bool Save the current flags first so hand-made flags can be recovered.

Returns¶

dict flagged_before / flagged_after fractions and the backup name.

get_metadata(project_code, source_names, observatory) ¶

Return full observation metadata: antennas, scans, frequency setup, sources.

Backends should populate as much of :class:~vlbipy.models.ObsMetadata as they can afford at inspection time — downstream steps (scan selection, reference-antenna ranking, imaging parameters) read it instead of re-querying the data.

get_subband_participation(project_code, antenna_names) ¶

Return {antenna: (subband indices with unflagged data, ...)}.

Heterogeneous VLBI arrays record different subband subsets per antenna; this is separate from :meth:get_metadata because it requires reading the flags and is therefore the expensive part of inspection.

read_spectrum(project_code, *, field='', scans=None, refant='', column='corrected', all_pols=False, **kwargs) ¶

Return time-averaged spectra on baselines to the reference antenna.

read_uvdistance(project_code, *, field='', column='corrected', time_bin=10.0, **kwargs) ¶

Return visibilities against uv distance, averaged per subband and in time.

read_timeseries(project_code, *, field='', refant='', column='corrected', max_time_bins=300, **kwargs) ¶

Return amplitude/phase vs time per baseline, averaged over frequency.

read_dynamic_spectra(project_code, *, field='', column='corrected', max_time_bins=200, stokes_i=True, **kwargs) ¶

Return a binned time x frequency array per antenna pair.

listobs(project_code, listfile=None) ¶

Return a scan/field listing of the imported data (optionally written to a file).

datasets(project_code) ¶

Return the visibilities as lazy datasets (dask-ms style backends only).

operations() ¶

Return the names of every operation this component declares.

supports(operation) ¶

Return True if this backend actually implements operation.

An operation counts as implemented when the concrete component overrides the stub declared on its ABC.

implemented() ¶

Return the operations this backend implements (a subset of :meth:operations).

CalibrationOps ¶

Bases: BackendComponent

Solve for and apply calibration.

Every method returns the :class:~vlbipy.models.CalTable it produced (or a list of them) so the caller can accumulate the gain-table chain without knowing anything about the backend's table format.

backend property ¶

The owning backend.

kind property ¶

The owning backend's short identifier (e.g. "casa").

work_dir property ¶

The owning backend's working directory.

a_priori(project_code, field, *, needs_eop=False, eop_file=None, **kwargs) ¶

Produce a-priori calibration tables (Tsys, gain curve, EOP, TEC, ...).

initial_calibration(project_code, field, refant, **kwargs) ¶

Single-band delay (instrumental) calibration on the fringe finder.

bandpass(project_code, field, refant, **kwargs) ¶

Bandpass calibration.

fringefit(project_code, field, refant, **kwargs) ¶

Global (multi-band delay) fringe fit.

scalar_bandpass(project_code, field, refant, **kwargs) ¶

Solve one amplitude gain per antenna and subband, removing inter-subband steps.

scan_snr(project_code, field, *, refant='', channel_fraction=0.8, scans=None, max_scans=0, **kwargs) ¶

Measure fringe SNR per scan, antenna and polarization on the calibrators.

A short fringe fit over the central channel_fraction of each subband, solved per scan, whose SNRs are read back into a :class:~vlbipy.models.ScanSNRSurvey. This is a diagnostic solve: its table is not added to the gain-table chain. Downstream it drives scan selection, reference-antenna ranking and the SNR matrix plot.

Parameters¶

project_code : str Project code. field : str Calibrator field selection (comma-separated names). refant : str Reference antenna; its own (sentinel) solutions are masked out. channel_fraction : float Fraction of central channels per subband to use (default 0.8). scans : list, optional Restrict the survey to these scans (default: all scans on field).

measure_edge_channels(project_code, table, *, threshold=6.0, **kwargs) ¶

Measure how many channels roll off at each subband edge, from the bandpass.

solution_coverage(project_code, table, metadata=None) ¶

Return {antenna: {subbands with an unflagged solution}} for a table.

smooth(project_code, table, **kwargs) ¶

Smooth an existing calibration table (delay/rate noise reduction).

apply(project_code, field, tables, **kwargs) ¶

Apply the accumulated calibration tables to a field.

FlagOps ¶

Bases: BackendComponent

Flagging.

Backends only need to implement :meth:run; the named modes below delegate to it, so a backend gets the whole flagging surface from one method and can still override any individual mode that needs bespoke handling.

backend property ¶

The owning backend.

kind property ¶

The owning backend's short identifier (e.g. "casa").

work_dir property ¶

The owning backend's working directory.

run(project_code, kind, *, field='', **kwargs) ¶

Run one flagging mode and return the fraction of data it flagged.

Parameters¶

project_code : str Project code. kind : str One of autocorr, edges, quack, tfcrop, aoflagger, from_file, manual. field : str Field selection (empty = all fields).

autocorr(project_code, **kwargs) ¶

Flag autocorrelations (never used in VLBI imaging).

edges(project_code, *, edge_fraction=0.1, **kwargs) ¶

Flag the outer channels of every subband.

quack(project_code, *, interval=0.0, **kwargs) ¶

Flag the first seconds of every scan.

tfcrop(project_code, *, field='', **kwargs) ¶

Time-frequency outlier flagging (calibrators only).

aoflagger(project_code, *, field='', strategy='default', **kwargs) ¶

Run AOFlagger (calibrators only; targets are protected).

measure_quack(project_code, *, field='', threshold=0.9, **kwargs) ¶

Measure per antenna how long each scan takes to reach full amplitude.

outliers(project_code, *, field='', threshold=5.0, dry_run=False, **kwargs) ¶

Flag visibilities that break the smoothness of their own baseline.

from_file(project_code, flagfile, **kwargs) ¶

Apply flags listed in an external flag-command file.

manual(project_code, **selection) ¶

Apply a manual flag selection (antenna / spw / timerange / ...).
