Project¶

The Project class is the central orchestrator for a VLBI data reduction project. It holds all metadata, configuration, backend references, and provides access to calibration, flagging, imaging, and diagnostic operations.

VLBIObs ¶

A campaign of one or more VLBI projects — the object users construct.

Parameters¶

project : str or list of str One project code, or several (a campaign). network : str, optional Observatory: "EVN", "VLBA" or "LBA". backend : str, optional Backend name ("dummy", "casa" or "aips"). If omitted, the config value is used ("casa" by default). Others not implemented. target, phasecal, fringe_finder, check_source : str or list, optional Convenience source-role declarations. refant : str or list, optional Preferred reference antenna(s). mode : str Observing mode ("continuum" by default). config : str or pathlib.Path or dict, optional User TOML config path or dict. work_dir : str or pathlib.Path, optional Base working directory. **overrides Extra nested-config overrides (deep-merged last).

import_data property ¶

Import namespace, fanned out across all observations.

calibrate property ¶

Calibration namespace, fanned out across all observations.

flag property ¶

Flagging namespace, fanned out across all observations.

plot property ¶

Plotting namespace, fanned out across all observations.

clean property ¶

Imaging namespace on the merged (or sole) observation.

selfcal property ¶

Self-cal namespace on the merged (or sole) observation.

export property ¶

Export namespace on the merged (or sole) observation.

sources property ¶

The shared source set (from the primary observation).

metadata property ¶

Observation metadata (None until :meth:import_data has run).

antennas property ¶

Antennas, keyed by name (empty until imported).

scans property ¶

Scan list (empty until imported).

frequency property ¶

Frequency setup (None until imported).

gaintables property ¶

Calibration tables accumulated so far, in application order.

refant property ¶

Reference antenna(s) in use.

calibrator_field property ¶

Field used for calibration: fringe finders, else phase cals, else targets.

observatory property ¶

The VLBI network.

work_dir property ¶

Working directory holding the data and products.

project_code property ¶

Project code(s) in this campaign.

snr_survey property ¶

The most recent per-scan fringe SNR survey (None until measured).

data property ¶

Lazy dask-ms datasets (dask-ms backend only).

observations property ¶

The list of per-project observations.

state property ¶

Aggregate step state, keyed by project code.

from_config(config, **kwargs) classmethod ¶

Build a VLBIObs entirely from a TOML config (project list included).

per_project(name) ¶

Return one observation's attribute, or {project_code: value} for a campaign.

Every read-only property below funnels through this, so a single-project campaign — the common case — reads exactly like the underlying :class:~vlbipy.observation.Observation (obs.metadata), while a multi-project one keeps the values labelled by project instead of collapsing them into an anonymous list.

Parameters¶

name : str Attribute name on :class:~vlbipy.observation.Observation.

merge(*, force=False) ¶

Combine calibrated data across projects (no-op for a single project).

Returns¶

Observation The merged observation (or the sole observation for one project).

run(*, force=False, scratch=False, from_step='') ¶

Run the full default pipeline end to end.

Resumes from the last completed step by default: progress is recorded in <work_dir>/.pipeline_state.json, so an interrupted run continues rather than redoing hours of calibration.

Parameters¶

force : bool Re-run steps even when they are already recorded as done. scratch : bool Start over — forget all progress and reset the data itself. from_step : str Re-run from this step onward (see observation.STEP_ORDER).

Returns¶

dict Mapping of target source name -> produced image(s).

reset() ¶

Clear state on every observation and drop any merge.

listobs(listfile=None) ¶

Return the scan/field listing(s) of the imported data (per observation).

report() ¶

Return per-observation report dicts (no files written in dummy mode).

summary() ¶

Return a combined human-readable summary of all observations.
